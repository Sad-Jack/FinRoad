# План ревью и проверки FinRoad

Дата составления — 4 ноября 2026 года.

Проверяется текущий локальный HTML и исходники. Персональные записи пользователя используются только при его отдельном указании. Проверки выполняются на синтетических данных в изолированных профилях браузера. Скриншоты и временные выгрузки сохраняются в исключённом из Git каталоге output/.

## Правила расчёта

- Начальный остаток задаётся вручную и не меняется при построении прогноза.
- Период таблицы включает сегодня и следующие 30 дней. Дата суммы в шапке задаёт отдельный горизонт расчёта от сегодня включительно.
- Итог равен начальному остатку плюс все приходы минус все расходы периода. Промежуточный минус не обнуляет итог.
- В один день сначала учитываются приходы, затем расходы.
- Регулярные платежи повторяются каждый месяц. Число 31 ограничивается последним днём месяца.
- Регулярные доходы переносятся на предыдущий рабочий день по встроенному производственному календарю. Доход следующего месяца может попасть в конец предыдущего.
- Остатки кредитов обновляются вручную. У кредитки долг равен максимуму из нуля и разницы лимита и баланса.
- Старые записи и резервные копии сохраняют совместимость.

## Распределение

Сначала три независимых ревью — архитектура, логика сценариев, правильность расчётов. После ревью три тестировщика выполняют группы A, B, C. Каждый фиксирует версию, сценарии, фактические результаты и дефекты. Проверки с исправлением повторяются на итоговой сборке.

## A. Расчёты и календарь

| ID | Сценарий и ожидаемый результат |
| --- | --- |
| A01 | Сверить вручную итог прогноза с нулевым, положительным и отрицательным начальным остатком. |
| A02 | Проверить границы периода — событие сегодня и в последний день включается, вчера и за горизонтом исключается. |
| A03 | Сравнить горизонты до первого и последнего дня следующего месяца. Все регулярные расходы повторяются. |
| A04 | Проверить декабрь–январь. Отдельно сверить доход января, перенесённый в декабрь, и отсутствие его повторного начисления в январе. |
| A05 | Проверить 28/29/30/31 в феврале високосного и обычного года, а также возврат к исходному числу в марте. |
| A06 | Выходные, праздники и рабочие субботы по календарю 2025–2027. Вне покрытия показывается предварительная дата. |
| A07 | Смешанный приход и расход одного дня, первый минус, итог после последующих поступлений. |
| A08 | Налог 0/13/100%, разделение 0/50/100%, дробные проценты и суммы с копейками. Сумма частей равна чистому доходу. |
| A09 | Несколько источников и повторяемые/разовые расходы, разные даты начала, несколько лет прогноза. |
| A10 | Сверить шапку и таблицу при одинаковом горизонте, при разных горизонтах проверить независимую арифметику обоих. |

## B. Платежи, долги и сохранение

| ID | Сценарий и ожидаемый результат |
| --- | --- |
| B01 | Создать и отредактировать каждый из пяти типов платежа. Достаточно названия и типа. |
| B02 | Регулярный платёж, разовая дата, несколько дат, пустые суммы/даты, переход между типами и режимами. |
| B03 | Ипотека всегда ежемесячная. Платежи по кредиту не уменьшают тело долга автоматически. |
| B04 | Кредитка — лимит/баланс, копейки, ноль, баланс выше лимита, отрицательный баланс, некорректные значения. |
| B05 | Старая кредитка без лимита и баланса. Изменение названия и частичное заполнение не теряют известный долг. |
| B06 | Погашения ограничены долгом с учётом остальных дат. Ошибка не меняет сохранённые записи. |
| B07 | Дедлайн и частичные погашения не дублируют сумму долга. Проверить неполные строки и прошедшие даты. |
| B08 | Совпадающие имена, связи по ID, изменение названия и удаление только выбранной записи с её расписанием. |
| B09 | Сохранение/повторное открытие/перезагрузка, экспорт–импорт, предыдущие форматы копий. |
| B10 | Повреждённый импорт, недоступное хранилище и конфликт двух вкладок не уничтожают данные. |

## C. Интерфейс и готовая сборка

| ID | Сценарий и ожидаемый результат |
| --- | --- |
| C01 | Открыть FinRoad.html через file:// без сервера. Внешние запросы для работы не нужны. |
| C02 | Навигация, создание/изменение/удаление дохода и платежа через обычные точки входа. |
| C03 | Календарь открывается кликом по полю, выбор даты шапки сразу обновляет сумму. |
| C04 | Провести через UI сценарий A04 и показать, откуда взялись доходы/расходы итогового прогноза. |
| C05 | Шапки трёх таблиц закреплены при прокрутке, без наложений при ширине 390/820/1440. |
| C06 | Дневная/ночная темы, длинные названия, большие суммы и пустые списки. |
| C07 | Центрирование крестика, закрытие диалога, Tab/Shift+Tab не перемещают фокус, текст доступен для копирования. |
| C08 | Барабан числа, календарь в диалоге, поля кредитки в одной строке и ограничения погашений. |
| C09 | Данные сохраняются после перезагрузки готового HTML, импорт и экспорт доступны. |
| C10 | Отсутствие ошибок JavaScript в проверенных сценариях и соответствие HTML текущим исходникам. |

## Формат результата

Для каждого случая — PASS, FAIL или NOT RUN с причиной. Для дефекта — приоритет, шаги, ожидаемый и фактический результат, место в коде и доказательство. Итоговые цифры относятся только к реально выполненным проверкам.
