# FinRoad

Локальное веб-приложение для личного финансового плана: когда придут деньги, какие платежи предстоят и сколько останется к выбранной дате. Компактный интерфейс с дневной и ночной темами.

Приложение работает на компьютере, хранит записи в SQLite и открывается в браузере. Подключения к банкам и синхронизации с Google Таблицами нет.

## Запуск

Нужны Python 3.9 или новее и современный браузер. Сервер использует только стандартную библиотеку Python — устанавливать зависимости не требуется.

```sh
git clone https://github.com/Sad-Jack/FinRoad.git
cd FinRoad
python3 server.py
```

Открой **http://127.0.0.1:8765**. Оставь терминал с сервером работающим; для остановки нажми `Ctrl+C`.

На macOS можно запустить файл `start.command` двойным кликом. Если система не разрешает его открыть, запусти команду выше из терминала в папке проекта.

Если порт занят, выбери другой:

```sh
python3 server.py --port 8766
```

Тогда адрес приложения — http://127.0.0.1:8766. Сервер принимает подключения только с этого компьютера.

## Первое использование

1. Нажми «Сейчас в наличии» в шапке и введи фактический остаток денег.
2. На вкладке «Доход» добавь источники дохода и даты выплат.
3. На вкладке «Платежи» добавь расходы и долги, укажи суммы и расписание.
4. На вкладке «План» смотри общий график и прогноз остатка после каждого события.

Данные сохраняются автоматически после сохранения формы. Луна или солнце в шапке переключают тему.

## План

План показывает результаты настроек платежей и доходов. Редактирование записей находится в соответствующих вкладках; отмечать оплату или получение денег не нужно.

- События идут по датам, внутри одного дня сначала доходы, затем расходы.
- Стрелки переключают месяцы. Назад можно перейти только до текущего месяца.
- «Свободно по …» показывает прогноз остатка на конец выбранной даты. По умолчанию это последний день показанного месяца; клик по дате меняет срок расчёта.
- Если в промежуточный день денег не хватает, справа в шапке таблицы появляется дата первого минуса и сумма остатка в этот момент. Предупреждение нельзя закрыть.
- Промежуточный минус не обнуляет «Свободно»: там остаётся итоговый остаток к выбранной дате с учётом последующих доходов и расходов.
- «Долг без ипотеки» в общей шапке суммирует указанные остатки кредитов, кредитных карт и личных долгов.

Прогноз учитывает только внесённые события. Текущий остаток денег и остатки долгов обновляй вручную. Проценты по кредитам и уменьшение тела долга автоматически не рассчитываются.

## Платежи

Кнопка «Добавить» открывает общую форму. Обязательны только название и тип. Нажатие на существующую запись открывает заполненную форму; в ней можно сохранить изменения или удалить запись.

| Тип | Расписание |
| --- | --- |
| Личное | Ежемесячно или в определённую дату |
| Кредит | Ежемесячно или несколько отдельных дат с суммами |
| Ипотека | Только ежемесячно |
| Личный долг | Отдельные погашения, можно разбить на несколько дат и сумм |
| Кредитная карта | Отдельные погашения, можно разбить на несколько дат и сумм |

Число ежемесячного платежа выбирается барабаном от 1 до 31 — колесом мыши, касанием или клавиатурой. В коротком месяце число, которого нет, заменяется последним днём: 31 всегда означает последний день месяца. Расходы на выходные не переносятся.

Для разовой даты кликни по полю целиком, чтобы открыть календарь. Запись с незаполненной суммой или датой можно сохранить и дополнить позже; неполное расписание не попадает в прогноз. Если остаток долга указан, сумма погашений ограничивается доступным остатком с учётом других запланированных погашений.

Список можно отфильтровать по типу. Записи сортируются по дате, записи без расписания находятся внизу.

## Доход

Источник дохода может быть ежемесячным или разовым. В форме задаются сумма до налога и процент налога; для нового источника налог предзаполнен значением 13%. Это задаваемый вручную процент, а не автоматический расчёт налоговых ставок.

Ежемесячный доход делится на зарплату и аванс в выбранных долях. Для каждой части указывается число от 1 до 31. Суммы после налога рассчитываются в копейках.

Если регулярная выплата попадает на нерабочий день, она переносится на предыдущий рабочий день. В проект включён производственный календарь России для пятидневной рабочей недели на **2025–2027 годы**, включая праздники и переносы. Региональные праздники не учитываются. Для лет вне календаря учитываются только суббота и воскресенье, а дата помечается как предварительная.

Просроченный доход не прибавляется к прогнозу как уже полученный. Обновляй фактический остаток, когда деньги поступили, или меняй расписание.

## Данные, импорт и экспорт

- База находится в `data/finroad.sqlite3` относительно папки проекта. При первом запуске создаётся пустая база.
- На вкладке «Платежи» кнопка «Экспорт» скачивает JSON с записями, а «Импорт» восстанавливает их из файла после подтверждения замены текущих данных.
- Делай экспорт перед большими изменениями и переносом на другой компьютер. Автоматических резервных копий нет.
- Для переноса базы целиком останови сервер и скопируй папку `data` вместе с проектом.
- База, экспортированные файлы, локальные скриншоты и логи исключены из Git. После клонирования репозитория твои финансовые записи сами не появятся — потребуется импорт или копирование базы.
- Выбор темы хранится отдельно в браузере.

При необходимости можно указать другой путь к базе:

```sh
FINROAD_DB=/absolute/path/finroad.sqlite3 python3 server.py
```

Приложение рассчитано на личную работу на одном компьютере. Пользовательских аккаунтов и облачного хранения нет.

## Проверки

Для тестов дополнительно нужен Node.js 20 или новее. Пакеты npm устанавливать не нужно.

```sh
npm test
```

Или запусти проверки отдельно:

```sh
node --test tests/*.test.mjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

Тесты проверяют финансовые расчёты, расписания, календарь выплат и серверное хранение. Серверные тесты используют временную базу.

## Структура проекта

```text
public/                 Интерфейс, стили и финансовые расчёты
reference/              Исходные JSON производственного календаря
server.py               HTTP-сервер и SQLite, без внешних библиотек
start.command           Запуск на macOS
tests/                 Проверки JavaScript и Python
data/                  Локальная база, не включается в Git
```

Календарные данные взяты из [XML Calendar](https://xmlcalendar.ru/). Исходные файлы находятся в `reference/calendar-ru-YYYY.json`, встроенный календарь приложения — в `public/work-calendar.js`. При расширении поддерживаемых лет нужно обновить оба представления и календарные тесты.
