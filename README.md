# FinRoad

Локальное веб-приложение для личного финансового плана: когда придут деньги, какие платежи предстоят и сколько останется к выбранной дате. Компактный интерфейс с дневной и ночной темами.

Приложение — один локальный HTML-файл. Работает без сервера, терминала, Python, установки пакетов и подключения к интернету. Записи сохраняются в хранилище браузера. Подключения к банкам и синхронизации с Google Таблицами нет.

## Открыть приложение

1. Скачай репозиторий через **Code → Download ZIP** и распакуй архив (или клонируй его).
2. Открой **`FinRoad.html`** в Chrome двойным кликом или через «Открыть с помощью».
3. Добавь открытую страницу в закладки (`⌘D` на Mac, `Ctrl+D` на Windows).

Теперь достаточно открыть закладку, поработать с финансами и закрыть вкладку. Отдельный процесс запускать не нужно. Для работы достаточно самого `FinRoad.html`: стили, код и календарь встроены в файл. В репозитории этот файл не содержит пользовательских записей.

На macOS `start.command` тоже открывает этот HTML-файл в браузере по умолчанию. Он больше не запускает сервер. Адрес `http://127.0.0.1:8765` больше не используется.

Используй один браузер, один профиль и постоянное расположение файла. Обновляй файл на том же месте, предварительно сделав экспорт данных.

## Первое использование

1. Нажми «Сейчас в наличии» в шапке и введи фактический остаток денег.
2. На вкладке «Доход» добавь источники дохода и даты выплат.
3. На вкладке «Платежи» добавь расходы и долги, укажи суммы и расписание.
4. На вкладке «План» смотри общий график и прогноз остатка после каждого события.

Переход между элементами по Tab отключён. Текст записей и содержимое полей можно выделять для копирования.

Данные сохраняются в браузере после сохранения формы. Луна или солнце в шапке переключают тему.

## План

План показывает результаты настроек платежей и доходов. Редактирование записей находится в соответствующих вкладках; отмечать оплату или получение денег не нужно.

- События идут по датам, внутри одного дня сначала доходы, затем расходы.
- По умолчанию таблица показывает сегодняшний день и следующие 30 дней включительно. При выборе даты «Свободно по …» таблица и сумма в шапке рассчитываются до этой даты включительно. Прошедшие операции исключаются из расчёта.
- «Свободно по …» показывает прогноз остатка на конец выбранной даты. По умолчанию это конец периода таблицы. Клик по дате меняет общий срок расчёта таблицы и суммы в шапке.
- Если в промежуточный день денег не хватает, справа в шапке таблицы появляется дата первого минуса и сумма остатка в этот момент. Предупреждение нельзя закрыть.
- Промежуточный минус не обнуляет «Свободно»: там остаётся итоговый остаток к выбранной дате с учётом последующих доходов и расходов.
- «Долг без ипотеки» в общей шапке суммирует указанные остатки кредитов, кредитных карт и личных долгов.
- Шапка плана с периодом и названиями столбцов остаётся закреплённой под верхней панелью при прокрутке длинного списка. На узких экранах закрепляется период, а подписи сумм отображаются в строках.

Прогноз учитывает только внесённые события. Текущий остаток денег и остатки долгов обновляй вручную. Прошедшие погашения остаются в настройках, но не вычитаются повторно из актуального долга и не занимают лимит будущих погашений. Проценты по кредитам и уменьшение тела долга автоматически не рассчитываются.

## Платежи

Кнопка «Добавить» открывает общую форму. Обязательны только название и тип. Нажатие на существующую запись открывает заполненную форму; в ней можно сохранить изменения или удалить запись.

| Тип | Расписание |
| --- | --- |
| Личное | Ежемесячно или в определённую дату |
| Кредит | Ежемесячно или несколько отдельных дат с суммами |
| Ипотека | Только ежемесячно |
| Личный долг | Отдельные погашения, можно разбить на несколько дат и сумм |
| Кредитная карта | Отдельные погашения, можно разбить на несколько дат и сумм |

Число ежемесячного платежа выбирается барабаном от 1 до 31 — колесом мыши, касанием или клавиатурой. В коротком месяце число, которого нет, заменяется последним днём: 31 всегда означает последний день месяца. Расходы на выходные не переносятся.

Для разовой даты кликни по полю целиком, чтобы открыть календарь. Запись с незаполненной суммой или датой можно сохранить и дополнить позже; неполное расписание не попадает в прогноз. Если остаток долга указан, сумма погашений ограничивается доступным остатком с учётом других запланированных погашений.

У кредитной карты задаются максимальный лимит и текущий баланс. Долг рассчитывается как разница лимита и баланса, минимум — ноль. Пока оба поля не заполнены, у старой записи сохраняется ранее указанный долг. Лимит и баланс входят в экспорт данных.

Список можно отфильтровать по типу. Записи сортируются по дате, записи без расписания находятся внизу. Панель вкладок и шапка таблицы закреплены под верхней панелью во время прокрутки.

## Доход

Источник дохода может быть ежемесячным или разовым. В форме задаются сумма до налога и процент налога; для нового источника налог предзаполнен значением 13%. Это задаваемый вручную процент, а не автоматический расчёт налоговых ставок.

Ежемесячный доход делится на зарплату и аванс в выбранных долях. Для каждой части указывается число от 1 до 31. Суммы после налога рассчитываются в копейках.

Если регулярная выплата попадает на нерабочий день, она переносится на предыдущий рабочий день. У такой строки показана исходная дата. Например, январская выплата может попасть в декабрь и увеличить декабрьский прогноз. В проект включён производственный календарь России для пятидневной рабочей недели на **2025–2027 годы**, включая праздники и переносы. Региональные праздники не учитываются. Для лет вне календаря учитываются только суббота и воскресенье, а дата помечается как предварительная.

Просроченный доход не прибавляется к прогнозу как уже полученный. Обновляй фактический остаток, когда деньги поступили, или меняй расписание.

Панель «Источники дохода» и заголовки её столбцов остаются закреплёнными под верхней панелью при прокрутке списка.

## Данные, импорт и экспорт

- Рабочие записи хранятся в `localStorage` браузера под ключом `finroad-state-v1`. Они не записываются внутрь HTML и не отправляются в GitHub или на сервер.
- На вкладке «Платежи» кнопка «Экспорт» скачивает JSON с записями, а «Импорт» восстанавливает их из файла после подтверждения замены текущих данных. Формат совместим с резервными копиями прежней версии.
- Делай экспорт после важных изменений и перед переносом на другой компьютер, в другой браузер или профиль. Автоматического сохранения резервной копии в файл нет.
- В режиме инкогнито записи не сохранятся после закрытия сеанса. Очистка данных браузера также может удалить записи.
- Для локальных адресов `file://` поведение хранилища зависит от браузера и не гарантируется веб-стандартом. Перемещение или переименование HTML может открыть отдельное пустое хранилище. В таком случае импортируй резервную копию. Подробнее: [MDN — localStorage для file URL](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage#description).
- Если браузер не смог сохранить изменения, приложение показывает ошибку. Повреждённые сохранённые данные не сбрасываются автоматически; доступен импорт резервной копии.
- Выбор темы также хранится в браузере.
- База прежней версии, экспорты, локальные скриншоты и настройки IDE исключены из Git.

### Переход со старой версии с SQLite

Старая база `data/finroad.sqlite3` не удаляется, но новая версия её больше не использует. Если у тебя уже есть JSON-экспорт, импортируй его в локальный HTML.

Для однократного извлечения записей из старой базы можно воспользоваться Python 3.9+:

```sh
python3 scripts/export_sqlite.py data/finroad.sqlite3 data/finroad-migration.json
```

Затем в `FinRoad.html` выбери **Платежи → Импорт** и укажи полученный JSON. Скрипт только читает базу, не запускает сервер и не перезаписывает существующий файл экспорта. После переноса Python для работы приложения не нужен.

## Разработка и проверки

Для изменения исходников нужны Node.js 20+ и Python 3.9+. Внешних зависимостей нет, `npm install` не требуется.

После изменения файлов в `public/` пересобери HTML и запусти проверки:

```sh
npm run build
npm test
```

Или без npm:

```sh
python3 scripts/build_standalone.py
node --test tests/*.test.mjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

Сборка читает только исходники из `public/`; финансовые данные в HTML не включаются. Тесты проверяют расчёты, календарь, сохранение, проверку импорта, конфликт версий вкладок, ошибки хранилища, сборку HTML и экспорт старой базы на временных данных.

План расширенной проверки и результаты ревью находятся в [docs/test-plan.md](docs/test-plan.md) и [docs/review-2026-11-04.md](docs/review-2026-11-04.md).

## Структура проекта

```text
FinRoad.html            Готовое приложение: открыть в браузере
public/                 Исходники интерфейса, расчётов и хранилища
reference/              Исходные JSON производственного календаря
scripts/                Сборка HTML и однократный экспорт старой SQLite
start.command           Открытие HTML на macOS, без сервера
tests/                  Проверки JavaScript и Python
data/                   Старая база и локальные копии, не включаются в Git
```

Календарные данные взяты из [XML Calendar](https://xmlcalendar.ru/). Исходные файлы находятся в `reference/calendar-ru-YYYY.json`, встроенный календарь приложения — в `public/work-calendar.js`. При расширении поддерживаемых лет нужно обновить оба представления, календарные тесты и пересобрать `FinRoad.html`.
